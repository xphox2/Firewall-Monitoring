                  Basics

                  Rules evaluate in their profile's layer: Device > Site > Default.
                  Lower runs first within this profile's layer; device-profile rules always run before site, before Default.
                  The rule auto-lifts after this many hours. Blank = never expires.

                  Scope — narrow further (optional)

                  The profile's assignments already decide where this rule runs. Use these only to narrow it to a single vendor/device/site within the profile.

                  Conditions

                  Action

                  Flap dampening

                  State alerts fire once per outage and stay silent while the link is down — even after you acknowledge — until it recovers and drops again. These settings control re-alerting when a link flaps up and down.
                  A link that was healthy this long before dropping is a genuine new outage — alert right away, bypassing the daily cap.
                  Rapid up/down cycles collapse to at most this many alerts per 24 h. 0 = no cap (alert every outage).

                  Threshold

                  CPU / memory / disk / session alerting is driven by these rules. Leave the threshold blank to inherit the Settings → Alerts / policy / device value (recommended); set it here to override for the rule's scope. To turn a type off, add a suppress rule.
                  Static fires at a fixed value; z-score fires at the device's own baseline + K·σ (static value acts as a floor).
                  Leave blank to use the current Settings → Alerts / policy / device threshold for this metric.
                  Recover only once the metric falls below this. Must be below the fire threshold. Blank = default band.
                  Deviations above the baseline before firing. Blank = 3.

                  Spike sensitivity

                  A spike fires when an interface's throughput stays above its seasonal (weekday/hour) baseline by K standard deviations for the sustain window. Leave these blank to inherit the Settings → Alerts spike sensitivity (recommended); set them to override for the rule's scope. To turn spikes off, add a suppress rule.
                  Higher = less sensitive. Blank = 3.
                  How long the spike must persist before alerting. Blank = 15.

                  Preview

                  Sample matches:
                  State rules match live device up/down events, not stored logs, so there is nothing to preview here. Scope the rule with conditions on event_type (interface_down / vpn_tunnel_down), interface_name, tunnel_name, or vendor.
                  Metric rules evaluate live device telemetry, not stored logs, so there is nothing to preview here. Scope the rule with conditions on event_type (cpu_high / memory_high / disk_high / sessions_high), metric, or vendor.
                  Spike rules evaluate live interface throughput vs a seasonal baseline, not stored logs, so there is nothing to preview here. Scope the rule with conditions on event_type (traffic_spike), interface_name, or vendor.
                  Trap rules match live SNMP traps (any trap type), not stored logs, so there is nothing to preview here. Scope the rule with conditions on trap_type (e.g. HA_MEMBER_DOWN, LINK_DOWN, or any vendor trap type), vendor, or source_ip.
                  sFlow detection rules match live detections — security (port scans, threat-intel hits, exfil, C2, DDoS), policy (cleartext, denied_then_allowed, unexpected_egress) and operational (capacity, sampling_backoff) — not stored logs, so there is nothing to preview here. Scope with conditions on source_ip (the subject: attacker, or victim for DDoS/deny-storm victims), detector, event_type (security_event / policy_event / operational_event), dst_ip/dst_port/protocol, or severity.
                  Device health rules match live device/probe events (offline, stale telemetry, interface errors, config changes, SSH host-key changes, probe data lag/truncation), not stored logs, so there is nothing to preview here. Scope with conditions on event_type (device_offline, telemetry_stale, interface_errors, config_change, ssh_host_key_changed, probe_data_lag, probe_data_truncated), interface_name, probe_id, method/changed_by (config changes), or fingerprint.
