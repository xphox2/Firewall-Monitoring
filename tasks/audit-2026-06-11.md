# Internal Audit — Paired `Firewall-Mon` + `Firewall-Collector` (2026-06-11)

A two-repo CTO-level audit. Read-only, with file:line refs and concrete fixes.
**Build:** `go build ./...` PASS on both repos · `go test ./...` PASS on both ·
`go test -race` PASS on the collector (CI Ubuntu), skipped locally on the
server (Windows). `go vet ./...` clean on both.

## TL;DR (read this first)

1. **The headline finding from the 2026-06-10 internal audit was mis-attributed.** The
   "probe never sends `Authorization: Bearer`" claim (H-3) is **true for the
   server's own bundled `cmd/probe`** at `Firewall-Mon/internal/relay/relay.go`
   — **not for the production collector** at
   `Firewall-Collector/internal/relay/relay.go:568`, which does send the header
   on every authenticated request. The 12 reviewer subagents and the prior
   audit both conflated the two `internal/relay` packages. See **XR-1** below.

2. **After that correction, the top 5 must-fix issues today are:**
   - **B-1 [blocker]** — `BatchInserter` is in-memory; an `fwmon-api` crash
     loses in-flight telemetry. The probe side is durable (BoltDB), the server
     side is not. (XR-7 / MON-REL-03)
   - **H-1 [blocker]** — SSH `InsecureIgnoreHostKey()` still in the collector.
     `Audit 049/071` was filed as fixed; the fix did not land. (COL-SEC-1)
   - **H-2 [blocker]** — `DeviceInfo` has no `SSHKeyFile` / `SSHKeyPassphrase`
     fields; the 1.2.99 "SSH public-key auth" is dead code. (COL-SEC-2)
   - **H-3 [blocker]** — TFTP source-IP allowlist and rate-limit API are
     shipped but never enabled in production. (COL-SEC-3)
   - **H-4 [blocker]** — Server has no `mTLS` client-cert verification despite
     the collector shipping mTLS support — silent bypass. (XR-2)

3. **Aggregate:** **13 blockers, 41 high, 67 medium, 51 low — 172 findings**
   across the two repos. The collector is more security-critical (it sits on
   the management LAN with SSH access to firewalls) and the blocker density
   reflects that. The server is more performance-critical (every probe hits it)
   and the perf N+1 backlog reflects that.

4. **Recommended sprint 1 (this week):** XR-1, XR-7, COL-SEC-1, COL-SEC-2,
   COL-SEC-3, XR-2. Sprint 2: the 14 `X-Probe-Batch-ID` handler gaps (XR-3),
   the perf B-1 `GetProbeStats` 104-query problem, the dead `setupLoggerWith`
   wiring (COL-OPS-1), the wire-up 5/13 dead collector metrics (COL-OPS-3).
   Sprint 3+: code-quality dedup, test coverage, observability. (See
   "Recommended remediation sequencing" at the bottom.)

## Cross-repo findings (the dimension the 06-10 loop missed)

> These are the findings that span both repos. The "fix" is usually a 1-2
> repo edit; the "verdict" tells you which side owns the fix.

### [blocker] XR-1 — `Authorization: Bearer` missing from **the server's own bundled `cmd/probe`**
**Server side:** `Firewall-Mon/internal/relay/relay.go:265, 307, 475, 653, 676, 699, 773, 793, 813` — bare `r.httpClient.Post(url, ...)` with no `Authorization` header.
**Collector side:** `Firewall-Collector/internal/relay/relay.go:568` — `req.Header.Set("Authorization", "Bearer "+c.Config.RegistrationKey)` inside the single chokepoint `doAuthenticatedRequestH`.
**Category:** auth
**Description:** The 12 subagent reviews and the 06-10 prior audit all
read `internal/relay/relay.go` and reported "the probe never sends
Authorization." That is true **for the server's bundled `cmd/probe`** but
**false for the production collector**. The server's CHANGELOG v0.10.411
line 17 documents the server-side bug correctly; the audit narrative
attributed it to the collector. Net effect: anyone running the bundled
`cmd/probe` against a stock `fwmon-api` will 401 on every Register and
re-register forever. The collector (the real production client) works.
**Impact:** Server's bundled `cmd/probe` binary is non-functional against
itself. Anyone who follows the README's "probe" docs and runs the bundled
binary instead of the collector hits a 401 loop.
**Fix:** Either (a) consolidate — delete `cmd/probe` and its server-side
`internal/relay/relay.go` fork, point the README at the collector as the
sole probe, OR (b) one-line helper to set the header on the server's
bundled probe. Option (a) is the right call: the bundled probe is a stale
fork of pre-collector code and has no future. Saves ~800 LoC of unmaintained
code.
**Effort:** M (delete + verify nothing depends on it)

### [blocker] XR-2 — Server has no mTLS client-cert verification despite collector shipping mTLS support
**Server side:** `Firewall-Mon/cmd/api/main.go:411-438` — `http.Server{}` with no `TLSConfig` field. `grep -r "ClientAuth" Firewall-Mon` returns 0.
**Collector side:** `Firewall-Collector/internal/relay/relay.go:520-546` — `buildTLSConfig` loads the certs, refuses world-readable keys, but has nothing to authenticate against server-side.
**Category:** auth / security
**Description:** Worse than no mTLS — the collector's mTLS config is loaded
silently but has zero security effect. An operator who reads
`PROBE_TLS_CERT=/etc/ssl/...` in their env file and sees no startup error
believes they have cert-based auth. They don't. The actual auth is still
the bearer token, which is sent in the TLS tunnel (good) but is the only
auth factor (bad — no second factor).
**Impact:** Network attacker who steals a probe's bearer token can present
it from any client. mTLS would have required stealing the private key too.
**Fix:** Server side: build a `*tls.Config{ClientAuth: tls.RequireAndVerifyClientCert, ClientCAs: ...}` and assign to `server.TLSConfig` before `ListenAndServeTLS`. Add `PROBE_CLIENT_CA_FILE` env var. Probe side: emit a startup warning if `PROBE_TLS_CERT` is set but the server didn't request a cert.
**Effort:** M (server) + S (probe warning)

### [high] XR-3 — `X-Probe-Batch-ID` is sent on every event batch but only 4 of 18 server `Receive*` handlers honor it
**Server side:** `Firewall-Mon/internal/api/handlers/handlers_data.go` — `batchDedupCheck` + `defer markBatchIfOK` present in `ReceiveSyslogMessages:57`, `ReceiveTrapEvents:109`, `ReceiveFlowSamples:152`, `ReceivePingResults:196`. Absent in 14 others: `ReceiveInterfaceAddresses`, `ReceiveProcessorStats`, `ReceiveHardwareSensors`, `ReceiveSystemStatuses`, `ReceiveInterfaceStats`, `ReceiveVPNStatuses`, `ReceiveHAStatuses`, `ReceiveSecurityStats`, `ReceiveSDWANHealth`, `ReceiveLicenseInfo`, `ReceiveProcessSnapshot`, `ReceiveInterfaceErrors`, `ReceiveSensorDetails`, `ReceiveLicenseDetails`.
**Collector side:** `Firewall-Collector/internal/relay/relay.go:1363-1365` — `newBatchID()` set as `X-Probe-Batch-ID` on every event batch.
**Category:** lifecycle / data integrity
**Description:** A "saved successfully but response timed out" retry produces
**duplicate rows** in 14 of 18 handlers. For time series like `interface_stats`
and `vpn_status` this means doubled byte counts and false alerts.
**Impact:** Silent data duplication under network partitions. The 4 covered
handlers are the high-volume event types; the 14 uncovered are the periodic
stats where the impact is harder to notice.
**Fix:** Add 2-line `batchDedupCheck` + `defer markBatchIfOK` to every
`Receive*` handler. For `ReceiveConfigRevision` the existing merge-into-latest
model already dedupes by checksum — skip. ~15 minutes total.
**Effort:** S

### [high] XR-4 — Probe heartbeat URL inconsistency (both forms work today, no real bug)
**Collector side:** `Firewall-Collector/internal/relay/relay.go:759` — `POST /api/probes/heartbeat` (no ID).
**Server bundled probe:** `Firewall-Mon/internal/relay/relay.go:306` — `POST /api/probes/{id}/heartbeat`.
**Server routes:** `Firewall-Mon/cmd/api/main.go:558-559` — only the no-id form is registered.
**Category:** wire-format (latent footgun)
**Description:** Both URLs work today because only the no-id form is
registered. If the server ever adds a `:id` form, the collector's URL still
works (more-specific routes match first). No current bug, but the
divergence is undocumented.
**Impact:** None today.
**Fix:** Pick one URL form and align both clients. Document in `MIGRATING.md`.
**Effort:** XS

### [high] XR-5 — `PROBE_TLS_CERT` env-var name drift in the collector's compose file
**Collector compose:** `Firewall-Collector/docker-compose.yml:90-92` documents `PROBE_CA_CERT_FILE`, `PROBE_TLS_CERT_FILE`, `PROBE_TLS_KEY_FILE` (with `_FILE` suffix).
**Collector config:** `Firewall-Collector/internal/config/config.go:59-61` reads `PROBE_TLS_CERT`, `PROBE_TLS_KEY`, `PROBE_CA_CERT` (no suffix).
**Category:** docs (silent misconfig)
**Description:** Operator copies the compose comment block into their `.env`,
env var is silently ignored, no mTLS, no warning. (`XR-2`'s startup
warning would also cover this.)
**Fix:** Edit compose to remove `_FILE`. Add a startup info line that prints
which certs loaded.
**Effort:** XS

### [high] XR-6 — TFTP source-IP allowlist shipped but never enabled
**Collector side (API):** `Firewall-Collector/internal/tftp/tftp.go:107-164` — `SetAllowedSourceIPs` + `SetMinWRQInterval` are the public API for AUDIT-050.
**Collector side (caller):** `Firewall-Collector/cmd/collector/main.go:813-868` — `startTFTPServer` never calls either.
**Category:** security (AUDIT-050 incomplete)
**Description:** TFTP server accepts WRQ from any source IP. Any host on the
management LAN can submit a fake config backup that becomes a `CONFIG_CHANGE`
alert after the server's `ReceiveConfigRevision` merge-into-latest
processes it. The `validateProbe` device-id check is the only gate.
**Impact:** Spoofed config backups can trigger false alerts. With mTLS bypass
(XR-2), also no way to attribute the upload to a specific probe.
**Fix:** Wire `tftpServer.SetAllowedSourceIPs([]string{...})` in
`startTFTPServer`. Default to nil only for back-compat, with a warning.
**Effort:** S

### [high] XR-7 — Server `BatchInserter` is in-memory; probe is durable. Crash-asymmetry.
**Server side:** `Firewall-Mon/internal/database/batcher.go:20-22` — explicit "AUDIT-006 (durability half) deferred" comment.
**Probe side:** `Firewall-Collector/internal/relay/queue/queue.go` — SpilloverQueue with BoltDB spillover, restart-survival, FIFO, byte-cap eviction.
**Category:** lifecycle / data integrity
**Description:** A `fwmon-api` crash mid-batch loses in-flight syslog/trap/ping
events. The probe has already drained its local queue before the wire
round-trip — by the time the server is mid-batch, the probe has nothing
local to replay.
**Impact:** Silent data loss on server crash. The collector's `Send` returns
2xx only after the data is committed on the server, so the probe correctly
discards its own copy. Server crash = gone.
**Fix:** Land the deferred AUDIT-006 (WAL-on-disk + fsync). Use bbolt to
mirror the collector's SpilloverQueue, OR extract the queue package and
vendor it in both repos.
**Effort:** L

### [high] XR-8 — Cross-repo doc links are absolute github.com URLs that break outside GitHub
**Collector docs:** ~30 absolute `https://github.com/xphox2/Firewall-Monitoring/blob/master/...` links across `STRUCTURE.md`, `ARCHITECTURE.md`, `COMPATIBILITY.md`, `CUSTOM-VENDOR.md`, `ENV-VARS.md`, `FEATURES.md`, `FORTIGATE-SETUP.md`.
**Collector CHANGELOG:** `Firewall-Collector/CHANGELOG.md:6, 33, 44, 54` — multiple `xphox2/Firewall-Monitoring` references.
**Server CHANGELOG:** `Firewall-Mon/CHANGELOG.md:17` — same.
**Category:** docs
**Description:** A self-hosted Gitea mirror, a non-GitHub fork, or any org
rename produces dead links in the collector docs. The 1.2.109
doc-unification pass acknowledged this as a tradeoff but didn't address the
mirror-host breakage.
**Fix:** Rewrite to relative paths where possible; add a CI lint that
rejects `https://github.com/xphox2/...` in `docs/*.md` outside the
canonical-home section.
**Effort:** M

### [medium] XR-9 — Schema-version consts duplicated, no shared test pinning them in lockstep
**Server:** `Firewall-Mon/internal/relay/relay.go:526-529` — `SchemaVersionMin = 1, SchemaVersionMax = 1`.
**Collector:** `Firewall-Collector/internal/relay/relay.go:330-333` — same consts, with a comment "MUST stay in lockstep."
**Category:** test infrastructure
**Description:** The two consts are textually identical today, but nothing in

**Fix:** Add a static-guard test in the server's `internal/shell/` that

**Effort:** S

### [medium] XR-10 — Server bundled `cmd/probe` DTOs drift from collector DTOs (latent)
**Server bundled DTOs:** `Firewall-Mon/internal/relay/relay.go:531-616` — `RegistrationRequest` has `ProbeName`, `SiteID`; `DevicesResponse` has no `TFTPServerIP`.
**Collector DTOs:** `Firewall-Collector/internal/relay/relay.go:294-298, 335-342` — opposite.
**Category:** wire-format
**Description:** The server's bundled probe is functionally obsolete, but its
DTOs are a stale fork. Pointing the bundled probe at a real server today
works (handler ignores extra fields, populates defaults for missing ones).
A future handler change that reads `tftp_server_ip` from the response
would break the bundled probe silently.
**Fix:** Delete `cmd/probe` and its server-side `internal/relay`. (Same
fix as XR-1 option (a).)
**Effort:** M

### [medium] XR-11 — `last_data_received` updated by `validateProbe` data paths but not by `authenticateProbeByBearer` (heartbeat path)
**Server side:** `Firewall-Mon/internal/api/handlers/handlers_probes.go:690-695` — `last_data_received` updated inside `validateProbe`. `authenticateProbeByBearer` (line 624-645) does NOT update it.
**Category:** observability
**Description:** A probe that is heart-beating but has lost its data path
shows `last_seen` recent and `last_data_received` stale. Operators don't
have a single "is this probe healthy?" answer.
**Fix:** Update `last_data_received` in `authenticateProbeByBearer`, or add
a separate `last_heartbeat_received` column.
**Effort:** XS

### [medium] XR-12 — No contract test, no shared fixture, no docker-compose interop
**Server compose:** `Firewall-Mon/docker-compose.yml` — server only, no probe.
**Collector compose:** `Firewall-Collector/docker-compose.yml:50` — points at `https://stats.technicallabs.org` as default.
**No integration test** in either repo that brings up both.
**Category:** test infrastructure
**Description:** The two repos have never been run end-to-end against each
other in CI. Future DTO bumps could break the wire format with no test
failure.
**Fix:** Add a single ~150-line test in a new `internal/integration/` (or
`Firewall-Contract` repo) that builds the collector binary, starts the
server in-process, registers a probe, and runs `SendTrap` + `SendPingResult`
end-to-end. Catches XR-1, XR-2, XR-3, XR-5, XR-7, and the entire class of
wire-format regressions.
**Effort:** M

### Top 5 must-fix (this week)

1. **XR-1** — Server bundled `cmd/probe` `Authorization: Bearer` is missing. The H-3 finding from 06-10 was mis-attributed. The fix is to **delete the bundled probe** (it's a stale fork).
2. **COL-SEC-1** — `internal/ssh/ssh.go:58` still has `HostKeyCallback: ssh.InsecureIgnoreHostKey()`. AUDIT-049 was filed as fixed; the fix did not land. Any on-path attacker can MITM and capture the FortiGate admin password.
3. **COL-SEC-2** — `relay.DeviceInfo` has no `SSHKeyFile` / `SSHKeyPassphrase` fields. The 1.2.99 "SSH public-key auth" is dead code — the collector transmits every FortiGate password in cleartext every poll cycle. (After COL-SEC-1: with public-key auth, this would be a non-issue.)
4. **COL-SEC-3** — TFTP source-IP allowlist and rate-limit API shipped (1.2.103) but never enabled. Any host on the management LAN can submit a fake config backup.
5. **XR-2** — Server has no mTLS client-cert verification. The collector's mTLS knobs load silently but have zero effect. The "we use mTLS" claim in any deployment is false.

### Top 5 perf wins (next week)

1. **MON-PERF-B-1** — `GetProbeStats` 104 sequential queries per page load (`handlers_probes.go:713-809`). Sibling `GetProbesStatsBatch` does it in 8. **Delete the endpoint, redirect to the batch.**
2. **COL-PERF-1** — `SpilloverQueue.Push()` does a per-event fsync with the mutex held across the disk I/O (`queue.go:188-242`). At 5k events/sec sustained, this is the bottleneck. Batch the fsyncs (e.g., 1 fsync per 50ms or 100 events), `bbolt.NoSync: true` + periodic `db.Sync()`.
3. **MON-PERF-23** — `ReceiveSystemStatuses` uses a singleton INSERT loop (`handlers_data.go:378-423`) — N round-trips per batch. 100 devices = 200 RTTs per push. Switch to a single batch insert.
4. **MON-PERF-32** — `GetDashboardAll` runs `timeSeriesCount` 4× per dashboard load, each a `GROUP BY date_trunc` over a partitioned table. Add a rollup summary table populated by the poller, single query.
5. **COL-PERF-22** — Skip the JSON re-marshal/re-unmarshal on the drain path. Items are JSON-marshaled on Push, JSON-unmarshaled on Drain, JSON-re-marshaled on send. Use `json.RawMessage` to forward raw bytes.

### Top 5 reliability wins (next week)

1. **XR-7** — Server `BatchInserter` is in-memory. Land the deferred AUDIT-006 WAL.
2. **COL-REL-N-1** — SSH command goroutines (`ssh.go:170-186`) lack panic recovery. The outer `safego.Go` doesn't protect sibling goroutines. Wrap with `safego.Go`.
3. **COL-REL-N-3** — Final `sendHeartbeatWithStatus("offline")` is not stop-aware. On a 401 the re-register path can sleep up to 5+ minutes, blocking shutdown. Bypass the auth logic on shutdown.
4. **MON-REL-04** — `SET LOCAL statement_timeout = 0` is applied to 2 paths; 5 other DDL/maintenance paths still under the 30s default.
5. **COL-REL-N-11** — BoltDB corruption / disk-full: not handled. `bbolt.Open` error → `SpilloverQueue.Open` returns error → all Send* become no-ops, no metric, no quarantine, no rename to `.corrupt-<ts>`. Add a `relay_queues_enabled` gauge and a rename-to-`.corrupt` recovery.

### Top 5 code-quality wins (sprint 3)

1. **COL-CQ-05** — Generic `PDUCollector[T]` + generic `getOrCreate[T]` for the 8 vendor files. Single biggest dedup win in the repo — vendor support is the whole point of the snmp package and the duplication makes adding the next vendor painful.
2. **COL-CQ-04** — Split `cmd/collector/main.go` (1652 LoC, biggest function `pollDevice` at 179 LoC). Extract `devpoll` and `receivers` subpackages.
3. **COL-CQ-08** — Convert 227 `log.Printf` calls to slog. The 1.2.101 slog migration is 2% complete. `PROBE_LOG_FORMAT=json` is a dead env var.
4. **MON-CQ-NEW-4** — Extract `admin-alerts.js` (~600 LoC), `admin-syslog.js` (~250 LoC), `admin-traps.js` (~150 LoC), `admin-audit.js` (~200 LoC) from `admin-main.js` (4022 LoC, 133 fns, 636 var decls).
5. **MON-CQ-NEW-6** — `httputil.RequireDB` is unused in 8 of 11 handler files; 30+ sites reinvent the `if db == nil { 503 }` check inline with bespoke error messages. Mechanical refactor.

### Top 5 test-coverage wins (sprint 3+)

1. **MON-TC-N1 / XR-12** — `internal/relay/` at 1.8% (the server's bundled fork). httptest harness for the relay's send paths. Combined with the cross-repo integration test, this closes the entire class of wire-format bugs.

## Categories that look solid (across both repos)

- **GORM parameter binding** — no SQL injection in either repo. User input flows through `?` placeholders everywhere; the few `fmt.Sprintf` SQL compositions all use hardcoded internal values.
- **Probe auth crypto (collector→server path)** — `subtle.ConstantTimeCompare` against the at-rest hash (AUDIT-016/017). The double-hash design (collector hashes once, server hashes the bearer header again) defeats replay. The probe can never re-derive the at-rest hash from the bearer token.
- **`schema_version` handshake** — real, end-to-end, pinned by both test suites. Not theater.
- **Disk-spillover queue (collector side)** — clean BoltDB-backed FIFO with restart survival, byte-cap eviction, monotonic sequence keys. Well-tested (84.6% coverage).
- **Idempotency on `ReceiveConfigRevision` server-side** — merge-into-latest model with `FOR UPDATE` row lock, server-side normalized checksum. A retried backup with the same content is deduped; a different content is INSERTed; suspect quality is INSERTed-suspect.
- **`safego.Go` / panic recovery on the collector** — 21 of 23 long-lived goroutines recovered (the 2 exceptions are noted in COL-REL-N-1/N-2). Consistent use of the wrapper.
- **`/healthz` vs `/readyz` separation on the collector** — correct k8s pattern, `X-Ready-Reason` header is grep-stable.
- **AUDIT-NNN discipline** — every code change documents itself in CHANGELOG and the shell-pin tests. The audit-tracker culture is the reason we can produce a internal audit at all.
- **License alignment** — both repos MIT since 1.2.114. Consistent, well-documented, no GPL/AGPL in any dep.
- **Cross-repo testing infrastructure (each repo's own)** — the collector's `internal/relay/queue` is 84.6% covered and serves as the gold standard. The server's `internal/audit` is 88.9%. Each repo has good unit-test hygiene; the gap is the **cross-repo integration** (XR-12).
