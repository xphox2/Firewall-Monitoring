## Top 5 — fix first

### 1. B-1 (perf) `GetProbeStats` — 104 sequential queries per page load
`internal/api/handlers/handlers_probes.go:727-793`
4 totals + 4 last-hour + a 24-iteration loop × 4 COUNTs = 104 round-trips serialized through the 15-conn pool. `GetProbesStatsBatch` already does it in 8 queries. Fix: delete the endpoint, redirect clients to the batch, or collapse the per-hour loop into one `GROUP BY date_trunc('hour', timestamp), probe_id`.

### 2. H-3 (security) Probe wire-format is broken — relay client never sends `Authorization: Bearer`
`internal/relay/relay.go:265, 307, 475, 653, 676, 699, 773, 793, 813` (zero `req.Header.Set("Authorization", ...)`)
Server: `internal/api/handlers/handlers_probes.go:670-688` requires the header and 401s without it.
Net effect: no probe can push data with the current client. Either the client is "in flight" and the fleet is silently broken, or the server check was bypassed and ingest is unauthenticated.
Fix: set `Authorization: Bearer <hashed-key>` on every `httpClient.Do`. Tests already assume the header is sent (`testhelper_test.go:57-59`).

### 3. H-1 (security) `/api/public/connections` leaks full fleet topology without auth
`internal/api/handlers/handlers_dashboard.go:425-426`
```go
var connections []models.DeviceConnection
if err := db.Gorm().Preload("SourceDevice").Preload("DestDevice").Limit(100).Find(&connections).Error; err != nil {
```
Public route group (`cmd/api/main.go:551`), no `public_visible` filter. Sibling `GetPublicDevices` honors the flag (`handlers_dashboard.go:26`); this one doesn't. Exposes device names, types, statuses for every source/dest pair.
Fix: `db.Gorm().Joins("SourceDevice").Joins("DestDevice").Where("SourceDevice.public_visible = ? AND DestDevice.public_visible = ?", true, true).Find(...)`.

### 4. H-2 (security) Login LRU rate-limiter fails open with a fresh full burst per new IP
`internal/api/middleware/middleware.go:85-92, 174-187`
`LoginRateLimiter` is 1 req/s with burst 5, then `AuthManager.ValidateCredentials` enforces a per-`username+IP` lockout at 5 attempts/15 min. When the 50k-IP LRU table fills, the eviction policy gives any "unknown IP" a fresh full burst — exactly the credential-spray scenario. An attacker with 50k+ unique source IPs (trivial from cloud/botnet) sustains 5 password guesses/sec against `admin` indefinitely; the per-username lockout never fires because each key is unique.
Fix: key the account-takeover lockout on **username alone**, or treat map-full as a 503 instead of fail-open burst.

### 5. B-1 (tests) `internal/relay/` at 1.8% coverage — 822 LoC of probe→server client, no behavior tests
`internal/relay/relay.go:151-822`
`NewRelayClient`, `Register`, `Heartbeat`, `SendTrap/SendPingResult/SendSyslogMessage/SendFlowSample`, `syncLoop`, `sendBatch`, `flushQueues`, `FetchDevices`, all 4 `ConvertModel*` functions — only `jitter()` is tested. A regression in `sendBatch` (e.g. retry consumes the queue twice) silently loses probe data; nothing in CI catches it.
Fix: `httptest.NewServer` driving Register, heartbeat 404 → un-approve transition, queue overflow FIFO drop, retry-on-500. ~200 LoC.
